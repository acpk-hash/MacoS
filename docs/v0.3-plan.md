# AgentBoard v0.3 — 多模态 AI 工作台设计方案

> 制定:2026-07-06(Fable 控制器)。执行:Opus 代理,按 T1→T5 顺序,每任务单独验收。

## 目标

在现有 "agent 客户端"(codex 驱动的任务/看板/聊天)之上,新增一个**直连 API 的多模态工作台**,对标 ChatGPT 官网体验:

1. **对话**:随时接入 API 的聊天界面,流式输出、附件(图片/文本文件)、会话管理、停止/重新生成、模型切换。体验第一。
2. **图像生成工作台**:prompt + 参数面板 + 画廊网格 + 单张下载。
3. **视频生成**:同一工作台内通过「+」切换模式/模型;中继当前无视频端点,先落地 UI 形态 + 异步任务队列骨架 + 运行时能力探测,端点开通后即插即用。
4. **工作流画布**:本地 agent 执行任务时,以画布(节点+连线)形式可视化每个任务的进展与时间轴。

## 已验证的 API 事实(2026-07-06 实测)

| 能力 | 端点 | 结果 |
|---|---|---|
| 聊天 | `POST /v1/chat/completions` | ✓ gpt-5.5 正常返回,标准 OpenAI 格式 |
| 模型列表 | `GET /v1/models` | ✓ gpt-5.2/5.2-pro/5.3-codex/5.4/5.4-mini/5.5/gpt-image-2 等 13 个 |
| 图像 | `POST /v1/images/generations` | ✓ gpt-image-2,本中继实测**返回 url 模式**(img.sulmes.com 图床),无 usage;官方协议只回 `b64_json` → **Rust 必须双模兼容(url 下载 / b64 落盘)** |
| 视频 | `POST /v1/videos` | ✗ 404,暂不存在 |

**关键设计约束**:
- 图床 URL 可能过期 → 生成成功后 **Rust 端立即下载到本地**(`%APPDATA%/agentboard/media/`),画廊永远读本地文件。
- WebView 内直接 fetch 中继会撞 CORS,且 API key 不得进前端 → **所有 API 调用走 Rust(reqwest)**,流式内容通过 Tauri 事件下发(沿用现有 `agent-event` 模式,新通道 `studio-event`)。
- API key/base_url 复用 v0.2 的 engine_config(读 `~/.codex/config.toml` + `auth.json`),不新增存储位置,不落 SQLite/日志。
- 视频能力探测:启动时 `GET /v1/models` 缓存 + 对 `/v1/videos` 的 404 判定,UI 显示「当前 API 未开通视频模型」。

## 信息架构

侧边栏新增分组:
- **工作台**(新):对话 / 生成(图像+视频同页,模式切换)
- **Agent**(现有):任务看板 / Agent 会话 / 工作流画布(新)
- 设置(现有)

统一输入框(composer)规范,对话与生成页共用组件:
- 「+」按钮 = 附件上传 + 模式/模型切换菜单(对标 ChatGPT 的 + 菜单)
- Enter 发送 / Shift+Enter 换行 / Esc 或停止按钮中断流式
- 拖拽、粘贴图片直接变附件

## 数据模型(SQLite V4 迁移)

```sql
chat_sessions(id, title, model, created_at, updated_at)
chat_messages(id, session_id, role, content, attachments_json, model, status, created_at)
  -- status: complete | streaming | stopped | error
gen_media(id, kind, prompt, model, params_json, local_path, source_url, status, error, created_at)
  -- kind: image | video;status: pending | running | done | failed
```

## 任务分解

### T1 — Rust 后端:relay 客户端 + V4 迁移 + 命令层
- `src-tauri/src/relay.rs`:models 列表、chat SSE 流式(reqwest bytes_stream 手解 `data:` 行)、图像生成+立即下载到本地、视频能力探测(404 感知)。
- DB V4 迁移(上表三张表)+ CRUD + 测试。
- Tauri 命令:`chat_send`(流式,事件 `studio-event`:delta/done/error,含 abort 支持)、`chat_stop`、`chat_sessions_*`、`image_generate`、`media_list/delete`、`studio_capabilities`。
- 验收:`cargo test` 全绿零警告;新增 ignored live 测试(真实调 chat + image)。

### T2 — 前端:对话页(ChatGPT 级)
- `src/pages/StudioChat.tsx` + zustand store:会话侧栏(新建/改名/删除/搜索)、流式渲染(react-markdown + rehype-highlight)、代码块复制、停止/重新生成、模型选择器(来自 models 缓存)、附件(图片→base64 content parts、文本文件→内联,拖拽+粘贴)、自动标题(首条消息截断)。
- 验收:`npm run build` 零错误;流式打字流畅、停止即断、刷新后会话完整。

### T3 — 前端:生成工作台(图像+视频)
- `src/pages/StudioGen.tsx`:左参数面板(模型/尺寸/数量)+ 右画廊网格(convertFileSrc 读本地);单张下载(save dialog)、删除、点开大图、重新生成(带回 prompt);「+」菜单切图像/视频模式与模型;视频模式=任务队列 UI 骨架 + 能力探测提示。
- 验收:真实生成一张图并出现在画廊、可下载;断网/API 错时错误态清晰。

### T4 — 工作流画布
- `@xyflow/react` 12(MIT);`src/pages/Canvas.tsx`:任务→会话→事件流映射为节点(命令/文件修改/回复),状态着色(运行=动画边,完成=绿,失败=红),节点点击看详情,底部时间轴;数据源=现有 SQLite events/sessions,运行中任务实时追加(监听现有 agent-event)。
- 验收:选择一个历史任务能完整重现执行图;正在运行的任务节点实时增长。

### T5 — 收尾发布 v0.3.0
- 统一视觉走查(Fable 亲自)、修 T2-T4 遗留、版本号、NSIS 构建、官网上传 + landing 更新。

## 风险
- SSE 手动解析的边界(多行 data、[DONE]、连接中断)→ T1 单测覆盖。
- 大 b64 附件撑爆 IPC → 附件限 10MB,图片压到 2048px。
- React Flow 在 WebView2 一般无问题,若遇渲染毛刺再关 `panOnScroll` 动画。
