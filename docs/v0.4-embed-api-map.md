```toml

[patch.crates-io]

tungstenite       = { git = "https://github.com/openai-oss-forks/tungstenite-rs",   rev = "9200079…" }
```

### Hard requirement: SEED the Cargo.lock from codex-rs
A fresh resolve of the git deps re-picks newest semver-compatible transitives and
breaks the build. Two failures hit and fixed this way:
- `allocative 0.3.6` + mismatched `hashbrown` → `starlark_map` E0277 (`HashTable: Allocative` not satisfied).
- `rama-utils 0.3.0-rc1` vs `rama-core 0.3.0-alpha.4` → `rama-core` E0432 (`OpaqueError` not found).

**Fix:** copy `codex-src/codex-rs/Cargo.lock` over the spike's `Cargo.lock` before the
first build. codex-rs pins ALL `rama-*` to `0.3.0-alpha.4` and `allocative` to `0.3.4`
consistently; seeding preserves those and only resolves the new root package.
Any consumer (incl. AgentBoard) MUST vendor/pin the same locked graph.

### Toolchain
- codex-rs `rust-toolchain.toml` pins **1.93.0**, but the tree builds cleanly on
  **stable 1.96.1**. **No nightly required.** codex crates use **edition 2024** (needs rustc ≥1.85).
- **v8 cross-drive symlink trap (Windows):** `codex-core → codex-code-mode → v8 147.4.0`
  is a *mandatory* dep (embeds a V8 JS engine). `v8/build.rs` creates a `gn_root` symlink
  **only when `OUT_DIR` and the crate source are on different drives**; on Windows that
  needs admin/Developer Mode and otherwise panics `Failed to create symlink`.
  **Fix:** keep `CARGO_HOME` (registry) and `CARGO_TARGET_DIR` on the **same drive**
  (we relocated `CARGO_HOME=D:\cargo-home`, target on D:). Then the symlink branch is skipped.
- **rustc stack crash on the edition-2024 crates:** parallel compile of
  `codex-utils-plugins` / `codex-rmcp-client` crashed rustc with `STATUS_STACK_BUFFER_OVERRUN`
  under memory pressure. Build the codex crates with **`cargo build -j 2`** to avoid it.

### Metrics (debug profile)
- Cold full build: ~15–20 min wall (dominated by v8 + aws-lc-sys; `-j 2` for the codex crates).
- Incremental rebuild after a spike-source change: **~75 s**.
- Binary size (debug, unstripped, incl. v8 + debuginfo): **205,651,968 bytes ≈ 196 MiB**.
  Release/stripped will be smaller but still large (V8 static lib is tens of MB).

## 2. Session lifecycle API (from `codex_core::prompt_debug` recipe)

```
Config::load_with_cli_overrides_and_harness_overrides(cli, ConfigOverrides{
    cwd, approval_policy, sandbox_mode, additional_writable_roots, codex_self_exe, .. })
AuthManager::shared_from_config(&config, enable_codex_api_key_env=false)   -> Arc<AuthManager>
ExecServerRuntimePaths::from_optional_paths(codex_self_exe, linux_sandbox_exe)
EnvironmentManager::from_codex_home(codex_home, Some(runtime_paths))       -> Arc<EnvironmentManager>
thread_store_from_config(&config, None); resolve_installation_id(codex_home)
ThreadManager::new(&config, auth, SessionSource::Exec, env_mgr,
    empty_extension_registry(), analytics=None, thread_store, state_db=None,
    installation_id, attestation_provider=None)
let NewThread{ thread_id, thread } = thread_manager.start_thread(config.clone()).await?;
thread.submit(Op::UserInput{ items, environments:None, final_output_json_schema:None,
    responsesapi_client_metadata:None, thread_settings:Default::default() }).await? -> sub_id
loop { let Event{ id, msg } = thread.next_event().await?; /* match msg */ }
thread.shutdown_and_wait().await;  thread_manager.remove_thread(&thread_id).await;
```

- `NewThread.thread_id` is the session/conversation id (also the resume key).
- `thread.next_event()` yields `Event { id, msg: EventMsg }` until `TurnComplete`.
- **Runtime requirement:** codex-core does deep synchronous work (V8 isolate init,
  config/env construction) that overflows Windows' 1 MB main-thread stack. Drive the
  runtime from a thread with a large stack **and** set `thread_stack_size`:
  ```rust
  std::thread::Builder::new().stack_size(256<<20).spawn(|| {
      tokio::runtime::Builder::new_multi_thread().enable_all()
          .thread_stack_size(64<<20).build()?.block_on(run())
  })
  ```

## 3. Op / EventMsg → AgentEvent mapping (draft)

`EventMsg` (`codex-src/codex-rs/protocol/src/protocol.rs:1137`) has ~90 variants.
Reference target: `D:\dev\agentboard\src-tauri\src\agent\events.rs` (`AgentEvent`).

| codex EventMsg (key fields) | → AgentEvent | notes |
|---|---|---|
| `NewThread.thread_id` / `SessionConfigured` | `SessionStarted{session_id,thread_id}` | thread_id from `start_thread` |
| `AgentMessage(AgentMessageEvent{message})` | `AssistantMessage{text}` | whole message |
| `AgentMessageContentDelta` | (stream) | optional token streaming; ignore or accumulate |
| `AgentReasoning` / `AgentReasoningRawContent` | `Reasoning{text}` | |
| `ExecCommandBegin` + `ExecCommandEnd(command,exit_code,aggregated_output)` | `CommandRun{cmd,exit_code,output_tail}` | pair by `call_id`; tail = last 2000 of `aggregated_output` |
| `PatchApplyEnd(changes:HashMap<PathBuf,FileChange>,success)` | `FileEdit{path,kind,diff,added,removed}` | one per entry; `FileChange::{Add,Delete,Update{unified_diff,move_path}}` gives kind+diff; count add/remove from diff |
| `TurnDiff(unified_diff)` | (enrich FileEdit) | whole-turn unified diff (spike saw 205 B) |
| `McpToolCallBegin/End`, `WebSearchBegin/End`, `ImageGeneration*` | `ToolCall{name,detail}` | generic tool surface |
| `TokenCount(info:TokenUsageInfo{last_token_usage:TokenUsage})` | `Usage{input_tokens,cached_input_tokens,output_tokens,reasoning_output_tokens}` | `info` is `Option` — skip when None |
| `TurnComplete(TurnCompleteEvent{last_agent_message,..})` | `TurnCompleted{}` | end of turn |
| `Error(ErrorEvent)` / `StreamError` / `TurnAborted(reason)` | `Error{message}` | |
| `ExecApprovalRequest` / `ApplyPatchApprovalRequest` | reply `Op::ExecApproval`/`Op::PatchApproval{decision}` | **not emitted** under `AskForApproval::Never` |

**Alternative (recommended) coarser path — item-centric, matches current events.rs:**
`ItemCompletedEvent{ item: TurnItem, .. }` (`protocol/src/items.rs:42`) carries typed items
`AgentMessage | FileChange | McpToolCall | WebSearch | Reasoning | Plan | UserMessage | …`.
AgentBoard's existing parser is already item-based (`RawItem`/`RawFileChange` in events.rs),
so mapping `ItemCompleted` → `AgentEvent` is the smallest change and avoids Begin/End pairing.
The granular `*Begin/*End` variants are only needed for live progress UI.

Op variants of interest: `UserInput` (start turn), `Interrupt` (→ `TurnAborted`),
`ExecApproval`/`PatchApproval` (approval replies), `Compact`, `ThreadSettings`.

## 4. Approval / sandbox config

```rust
ConfigOverrides {
    approval_policy: Some(AskForApproval::Never),           // full-auto, no *ApprovalRequest events
    sandbox_mode:    Some(SandboxMode::DangerFullAccess),   // or WorkspaceWrite for real sandboxing
    additional_writable_roots: vec![sandbox_dir],
    cwd: Some(sandbox_dir),
    codex_self_exe: Some(<path to installed codex.exe>),    // exec-server re-spawns this for shell cmds
    ..Default::default()
}
```
- `AskForApproval` / `SandboxMode` from `codex_protocol::{protocol,config_types}`.
- `codex_self_exe` must point at a real codex binary (the exec-server re-execs it to run shell
  commands). We used the installed `…\OpenAI\Codex\bin\<hash>\codex.exe`.
- For a locked-down product use `SandboxMode::WorkspaceWrite` + writable roots instead of DangerFullAccess.

## 6. Known relay result & caveat

Full turn ran against the **aiboys relay** (user's `~/.codex`, apikey mode, `wire_api="responses"`, model `gpt-5.5`).
Event sequence observed:
`McpStartupUpdate… → TurnStarted → RawResponseItem×3 → ItemStarted/Completed → UserMessage →
AgentMessageContentDelta×N → AgentMessage("Creating hello.txt…") → PatchApplyBegin →
PatchApplyEnd(success=true, files=[…\sandbox\hello.txt]) → TurnDiff(205B) → TokenCount → TurnComplete`.
`sandbox/hello.txt` created with content **`embedded works`**. Relay connectivity: **OK**.

**Intermittent debug-only panic:** first run panicked
`OutputTextDelta without active item` at `core/src/util.rs:94`. That site is `error_or_panic`,
which **panics only under `debug_assertions`** and otherwise logs `error!` and continues.
It is a streaming-order assertion triggered by the relay's SSE delta ordering; the retry
completed cleanly. **Mitigation:** run the adapter in **release** (debug_assertions off), or
tolerate/retry — do not rely on debug builds for streaming stability.

## 7. Impact on AgentBoard main workspace (E2 guidance)

- **Toolchain: compatible.** AgentBoard `src-tauri` is edition 2021 on default **stable 1.96.1**,
  no `rust-toolchain.toml`. codex-core builds on the same stable — **no nightly, no channel split.**
  codex crates' edition 2024 is fine (rustc ≥1.85). Keep `-j 2` for CI to dodge the rustc stack crash.
- **Binary bloat is the headline cost.** codex-core drags in **V8** (mandatory via code-mode),
  aws-lc-sys, rama, starlark, tree-sitter → debug binary ~196 MiB. A Tauri desktop bundle would grow
  by tens–hundreds of MB. This is the strongest argument for keeping codex out-of-process.
- **Workspace coexistence risks:**
  - Cargo.lock must pin the entire codex transitive graph (seed from codex-rs). Merging into the
    tauri workspace forces one unified resolve — verify feature unification with AgentBoard's
    `reqwest(rustls-tls)`, `rusqlite`, `tokio` doesn't shift codex's pinned versions.
  - V8 cross-drive symlink: AgentBoard repo on D: with registry on C: hits the same trap — devs
    need `CARGO_HOME` on the repo drive or Windows Developer Mode.
  - Runtime needs a big-stack thread (256 MB) + `thread_stack_size(64 MB)` — incompatible with a
    plain `#[tokio::main]`; Tauri's runtime setup must account for it.
- **Adapter size estimate:** small. One module: build the stack (~40 lines, section 2), a
  `match EventMsg`/`ItemCompleted` → `AgentEvent` mapper (~80–120 lines, section 3), plus
  thread_id↔rollout bookkeeping for resume. The current JSONL parser in events.rs is directly reusable
  in shape.
- **Recommendation:** feasible but with conditions. Given the V8/binary-size and build-fragility cost,
  prefer an **out-of-process codex (sidecar) that the adapter maps the same way**, OR embed only if the
  bundle-size hit is acceptable and CI pins lock + `-j2` + same-drive CARGO_HOME.
