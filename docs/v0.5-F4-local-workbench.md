# F4 设计:第三功能改造 — codex 式本地工作平台(pi 内核)

> 用户方向(2026-07-07):画布做简单一点;第三个主功能不该是画布,而应是"类似 codex 的本地工作平台",可切模型改本地文件;**内核集成 pi CLI**,输出风格参考 pi;出现 **Claude-Code 式进度条**,可监控 agent 工作进度与 **token 消耗**。

## 一、结论:pi 用 RPC 模式做内核,干净可行

pi = `@earendil-works/pi-coding-agent` v0.80.3(本机全局已装,`dist/cli.js`)。它自带**无头 RPC 协议**,专为嵌入设计——这正是内核接口,且**避开**了之前 `pi -p` 后台卡死的坑(那是非交互一次性模式;RPC 是长驻双向流)。

启动:`pi --mode rpc --provider <p> --model <m> [--session-id <id>] [--cwd 由进程工作目录决定]`
- **stdin**:每行一个 JSON `RpcCommand`
- **stdout**:每行一个 JSON `RpcResponse`/事件
- **stderr**:日志

### 我们要用到的 RpcCommand(已从 rpc-types.d.ts 核实)
| 命令 | 用途 |
|---|---|
| `{type:"prompt", message, images?, streamingBehavior?}` | 发一轮任务 |
| `{type:"steer", message}` / `{type:"follow_up", message}` | 运行中插话 / 排队追问 |
| `{type:"abort"}` | 中断当前轮(进度条的停止按钮) |
| `{type:"set_model", provider, modelId}` / `{type:"get_available_models"}` | **切模型**(接 F1 的多服务商) |
| `{type:"set_thinking_level", level}` | off/minimal/low/medium/high/xhigh |
| `{type:"get_session_stats"}` | **token 用量**:`tokens{input,output,cacheRead,cacheWrite,total}` + 消息/工具计数 |
| `{type:"export_html", outputPath?}` | 会话导出 HTML(接 F5 沉淀) |
| `{type:"get_entries", since?}` / `{type:"get_tree"}` | 拉取/增量会话条目 |
| `{type:"new_session"}` / `{type:"switch_session", sessionPath}` / `{type:"fork", entryId}` | 会话生命周期 |

### 输出事件
`RpcResponse`(带 `id` 关联命令)+ 流式通知(assistant 文本增量、thinking、bash/tool 执行开始与结果、错误、轮结束)。适配器把它们映射到我们的进度 UI 与本地文件变更展示。pi 内置工具:read / bash / edit / write —— edit/write 即"改本地文件",bash 即命令执行,天然满足需求。

## 二、产品形态

### 侧边栏「Agent」组调整
- **画布 → 简化**:去掉详情抽屉/时间轴/自定义节点那套重实现,保留一个轻量"执行流"视图(纵向步骤列表 + 状态点),或直接降级为任务详情里的一个小组件。不再作为独立主功能位。
- **新增「工作台」**(第三主功能,codex 风):这是本任务重点。

### 工作台页 `src/pages/Workbench.tsx`
布局参考 codex/pi 终端观感,暗色:
1. **顶栏**:工作目录选择器(打开本地文件夹,pi 进程 cwd 指向它)、模型下拉(复用 F1 的 ModelPicker,选中即发 `set_model`)、thinking 级别、token 计量徽章(实时 total / 本轮增量,数据来自 `get_session_stats`,每轮结束刷新)。
2. **主区 = pi 风格输出流**:仿 pi CLI 的排版——
   - 用户输入行、assistant 流式文本(markdown)、thinking 折叠块;
   - **工具调用卡片**:bash(命令 + 输出,等宽)、edit/write(文件路径 + diff,复用现有 diff 展示);
   - 配色/前缀符号尽量贴近 pi 的终端风格(参考 `dist/modes/interactive/components/` 的 assistant-message/bash-execution 观感,不照抄代码,取神)。
3. **Claude-Code 式进度条**:运行中在底部/顶部显示一条活动进度指示——当前动作文案("正在编辑 x.ts"/"运行命令"/"思考中")+ 已用 token + 计时 + 停止按钮(发 `abort`)。轮结束收起。
4. **左侧(可选)文件树**:显示 cwd 下被 agent 触碰过的文件,点击看最新 diff。

### 与 F1 的关系
模型下拉/服务商来自 F1;pi 的 provider/model 用 F1 选中的服务商(把 base_url/key 通过环境变量或 `--api-key` 注入 pi 进程)。**F4 依赖 F1 完成**。

## 三、技术实现

### Rust:`src-tauri/src/pi_engine.rs`(新 sidecar 管理器,独立于 codex embedded)
- 解析 pi 启动路径:全局 npm(`%APPDATA%/npm/pi.ps1` 的 node + cli.js)→ 设置项覆盖;找不到给清晰引导("需安装 pi:npm i -g @earendil-works/pi-coding-agent")。首版依赖用户已装的 pi;后续可评估随包分发。
- spawn `node cli.js --mode rpc ...`,注入 F1 选中服务商的 `OPENAI_API_KEY`/base_url(环境变量,不写盘、不入日志)。
- stdin 写 RpcCommand;stdout 按行读 → 反序列化 → 转成我们的 `WorkbenchEvent`,经 Tauri 事件 `workbench-event` 下发。
- 命令:`workbench_open{dir,provider_id,model}`、`workbench_prompt{text}`、`workbench_steer`、`workbench_abort`、`workbench_set_model`、`workbench_stats`、`workbench_export_html`、`workbench_close`。
- 崩溃重启 + 优雅关闭(照 bridge.rs / embedded.rs 现有 sidecar 模式)。
- 会话/条目落我们 SQLite(接 F5 沉淀):每轮的 entries、stats、export_html 路径。

### 前端
- `src/stores/workbenchStore.ts`:cwd、运行态、输出条目流、当前进度、token 累计、文件变更集;全局单监听 `workbench-event`。
- `Workbench.tsx` + 子组件(OutputStream / ToolCard / ProgressBar / TokenBadge / FileTree)。
- 路由 `/workbench`,侧边栏「Agent」组加入口;画布入口降级/简化。

## 四、风险与对策
- **pi 后台稳定性**:历史上 `pi -p` 卡死(见记忆 [[pi-background-stall-sonnet-fallback]]),疑为中继鉴权失效时挂起。RPC 长驻模式不同,但仍要:启动后设握手超时(如 20s 无任何事件即判失败并提示),abort/close 用 taskkill 兜底,进程僵死时 UI 明确报错而非无限转圈。
- **pi 版本漂移**:RPC 协议可能随 pi 升级变化;版本 pin 建议 + 适配器对未知事件类型宽容跳过。
- **凭据注入**:只经环境变量传给子进程,绝不进 stdin 日志 / SQLite / 前端。
- **与 codex embedded 并存**:两个内核(codex 内嵌引擎、pi 工作台)定位不同——看板任务用 codex,工作台交互用 pi;互不干扰,各自 sidecar。

## 五、分解(F4 执行时拆成子任务)

- F4b:Workbench.tsx 全套前端(pi 风格输出流 + 进度条 + token 徽章 + 文件树)。
- F4c:画布简化 + 侧边栏信息架构调整。
- 依赖:F1 完成后开工(要 ModelPicker 与服务商凭据)。
