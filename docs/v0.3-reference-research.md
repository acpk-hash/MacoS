# AgentBoard v0.3 开源参考调研

> 调研日期: 2026-07-06 · 目标栈: Tauri 2 + React 18 + TypeScript + Tailwind 3.4
> 结论先行,每功能给可直接用的库 + 设计参考,并标注 license 商用风险。

## 结论速览(先抄这些)

| 功能 | 首选(可直接用) | 设计参考 | license 风险 |
|---|---|---|---|
| 1. 聊天界面 | **assistant-ui**(MIT,React 组件库) + **@ai-sdk/react** 的 `useChat` | lobe-chat / Open WebUI / NextChat | 低(MIT) |
| 2. 图像工作台 | **InvokeAI 前端**(Apache-2.0,React) | lobe-chat 绘图页 / Fooocus 参数分组 | 低(Apache-2.0) |
| 3. 视频生成 UI | 无现成 React 库;自建异步任务队列 | OpenAI `openai-sora-sample-app`(Next.js) | 参考实现 |
| 4. 工作流画布 | **@xyflow/react 12.x**(MIT) | Flowise / Dify / LangGraph Studio 画布层 | 低(MIT) |

关键判断:
- **聊天真正能"拿来即用"的只有 assistant-ui**(shadcn 风格 primitives + 内置流式/附件/markdown/代码高亮/停止/重生成)。lobe-chat / Open WebUI / NextChat 体量大、耦合自身后端与非 Tailwind 样式,**只作设计参考**,不建议抽组件。
- 图像/视频没有"复制粘贴即用"的 React 组件库,抄的是**页面形态与交互模式**;InvokeAI 是唯一 React + 商用友好的完整前端。
- React Flow 12 是画布层事实标准,MIT,Tauri/WebView2 无致命阻断问题(仅需常规 memo 优化)。

## 1. ChatGPT 级聊天界面

**可直接用的 React 组件库(优先级最高):**

- **assistant-ui/assistant-ui** — ~6.1k★,**MIT**。TypeScript/React 组件库,composable primitives:`Thread / Message / Composer / ThreadList / ActionBar`。开箱即有**流式、自动滚动、重试(regenerate)、附件、markdown、代码高亮、语音输入、键盘快捷键、可访问性**。提供 shadcn/ui 主题(CLI copy-in,像 shadcn 一样把源码拷进项目 → 可任意改样式,契合 Tailwind)。`useChatRuntime` 直连 Vercel AI SDK,也可换 `useLangGraphRuntime` / 自定义 runtime 接我们自己的中继后端。**这是 v0.3 聊天层的地基首选**。
  - 抄什么:直接用其 primitives 搭 Thread + Composer + ThreadList(会话管理),ActionBar 做停止/重生成/复制。
- **vercel/ai(AI SDK)+ @ai-sdk/react 的 `useChat`** — AI SDK 本体 MIT。`useChat` hook 管理消息流、streaming、停止(`stop()`)、附件与 tool 调用状态。**与 assistant-ui 组合是黄金搭档**(assistant-ui 管 UI,ai-sdk 管流式状态)。注意 v6 API。
- **vercel/chatbot(ai-chatbot 模板)** — Next.js 模板,MIT。**是应用模板不是组件库**,深度绑定 Next.js RSC/Server Actions + Postgres/Auth,Tauri(纯 CSR)下不能直接搬,但**会话持久化、消息分支、附件上传的交互设计值得抄**。

**仅作设计参考(不抽组件):**

- **lobehub/lobe-chat** — ~79.6k★,**LobeHub Community License**(基于 Apache-2.0 但**加了商用限制**:作为前后端服务用可以,但基于它做衍生产品分发需商业授权)。TS 98.9%,样式用 **antd-style(CSS-in-JS,非 Tailwind)**。→ **license 与样式栈都不适合抽代码**,只看设计:消息气泡、思考(reasoning)折叠、Artifacts 侧栏、绘图页。
- **open-webui/open-webui** — ~137k★。license 已从 MIT 改为**带 Anti-Endorsement / 品牌保护条款的 BSD-3 变体 + CLA**(超过一定用户量禁止去除 Open WebUI 品牌)→ **商用借鉴前需读 license,谨慎**。前端是 **Svelte 不是 React**,只看交互。
- **ChatGPTNextWeb/NextChat** — ~87k★,**MIT**,~5MB 客户端。轻量、跨平台(含桌面)。但技术栈自成一体,**参考其轻量会话管理与快捷交互**即可。
- Jan / chatbox:桌面聊天客户端设计参考;chatbox 非完全开源、部分功能订阅墙,**不建议作为代码来源**。

## 2. 图像生成工作台(prompt + 参数面板 + 画廊 + 下载)

- **invoke-ai/InvokeAI** — ~27.6k★,**Apache-2.0(商用友好)**,前端 **React + TypeScript**(TS 占 50%)。**唯一 React + 商用友好的完整图像前端**。
  - 抄什么(精确到页面/组件):
    - **左侧参数面板**:model / prompt / negative prompt / 尺寸 / steps / CFG / seed 分组折叠布局。
    - **中部画廊系统(gallery)**:网格缩略图、元数据回填(点击历史图 → 恢复当时 prompt/参数)、右键 remix。
    - **Unified Canvas**(若日后做局部重绘/inpaint 可参考,v0.3 可先不做)。
    - 下载/元数据嵌入图片的做法。
- **lobehub/lobe-chat 绘图页** — 主界面有 "Drawing" 入口,文本→图(DALL·E 3 / Flux 等)。**参考其 prompt 输入 + 生成结果画廊的极简布局**(license/样式同上,仅看形态)。
- **lllyasviel/Fooocus** — ~40k★+。**Gradio 实现,非 React**,不能抄代码。但其**"只填 prompt,参数智能隐藏/高级折叠"的极简参数哲学**值得借鉴——适合给 AgentBoard 做"简单/高级"两档参数面板。

建议:**布局抄 InvokeAI(参数面板 + 画廊网格),交互简化抄 Fooocus(参数分档)**,自己用 Tailwind 重写组件。

## 3. 视频生成 UI(异步任务队列 + 轮询 + 预览 + 模型切换)

现状:**没有成熟的开源 React 视频生成 UI 组件库**。重点是**异步任务队列的 UI 形态**与 **OpenAI 视频 API 标准流程**(我们中继暂无视频端点,先按标准设计以便日后接入)。

**参考实现:**
- **openai/openai-sora-sample-app** — 官方 Sample,展示 Video API(Sora)用法。**Next.js**,参考其任务提交 → 状态轮询 → 预览播放的组件划分。
- UI 形态抄:**任务队列列表**(每行:缩略图/占位、prompt、模型 badge、状态 chip queued/in_progress/completed/failed、进度条百分比、取消/下载)。轮询驱动局部更新。

**OpenAI `/v1/videos`(sora-2)标准流程(日后接入用):**
1. **创建**:`POST /v1/videos`,body 含 `prompt` / `model`(如 `sora-2` / `sora-2-pro`) / `size` / `seconds(duration)`。返回 job 对象含 `id` 与初始 `status`。
2. **轮询**:`GET /v1/videos/{video_id}`,读 `status`(`queued` → `in_progress` → `completed` / `failed`)与 `progress` 百分比。建议 **10–20s 间隔,指数退避**;或用 webhook(`video.completed` / `video.failed`)。
3. **下载**:`GET /v1/videos/{video_id}/content`,流式返回 MP4 二进制,直接存盘或转存。

设计要点:任务队列做成**可持久化的本地状态**(Tauri 侧存 job id + status),前端轮询;模型切换即改创建请求的 `model` 字段。此异步队列模式可**复用于图像批量生成**。

## 4. 工作流 / 执行画布

**核心库:@xyflow/react(React Flow 12)**
- **xyflow/xyflow**,最新 `@xyflow/react` **12.11.x**,**MIT license(完全商用友好)**。v12 起包名由 `reactflow` 改为 `@xyflow/react`。
- v12 新增:SSR/SSG、computing flows、dark mode、TSDoc、可为节点预定义 width/height/handles。
- **React 18 完全兼容**;样式与 Tailwind 不冲突(自带少量 CSS,节点内容随意用 Tailwind)。
- Bundle:未查到官方精确数字(npm/bundlephobia 待核)。经验上核心包 gzip 约几十 KB 级别,可接受;需要时按需引入。

**基于它的 agent 执行可视化(抄画布层设计):**
- **FlowiseAI/Flowise** — "Build AI Agents, Visually",**React 前端 + React Flow**,列于 React Flow 官方 showcase。**AgentFlow V2**:每个节点是独立执行单元,节点间连线显式定义执行路径/控制序列。**抄:节点端口(handle)语义、节点配置抽屉、执行时节点高亮/状态流转**。
- **Dify** — 开源 LLM 应用平台,画布同样基于 React Flow(showcase 收录)。**抄:workflow 编排的节点分类侧栏、变量引用 UI、运行态逐节点日志面板**。
- **LangGraph Studio** — agent 图执行可视化。参考其**执行轨迹回放 / 节点状态(运行中/成功/失败)可视化**,契合 AgentBoard "执行画布"诉求。

**React Flow 在 Tauri / WebView2 的已知问题:**
- **无致命阻断**。风险主要是通用性能:
  - WebView2(Windows)比 Electron 自带 Chromium 略慢,大图冷启动/复杂 CSS 动画/阴影/渐变会放大卡顿。
  - React Flow 自身性能坑是**不必要重渲染**:节点拖动触发频繁 state 更新。
  - **对策**:自定义节点用 `React.memo` 或定义在父组件外(避免每次 render 新引用);避免在拖拽/缩放时直接订阅整个 nodes/edges;精简节点 CSS(少用 shadow/gradient/animation)。
- 结论:**可安全用于 Tauri**,只需遵循 React Flow 官方 performance 指南 + 控制节点样式复杂度。

## 附:OpenAI 兼容 `/v1/images/generations`(gpt-image-1 / gpt-image-2)

**请求关键参数:**
- `prompt`(必填)、`model`(如 `gpt-image-1`)、`n`、`size`、`quality`。
- `size`:GPT image 模型支持 **`1024x1024` / `1536x1024`(横)/ `1024x1536`(竖)**,以及 `auto`(自动)。
- `quality`:**`high` / `medium` / `low`**(GPT image 模型);旧 DALL·E 的 `standard/hd` 不通用。
- `response_format`:**gpt-image-1 不支持该参数** —— **始终返回 base64**。

**响应格式:**
- 返回 `{ created, data: [ { b64_json: "..." } ], usage }`。
- **关键差异:gpt-image-1/2 只给 `b64_json`,不给 `url`**(DALL·E 3 才支持 `url`)。→ 前端需 **base64 → Blob/data URL** 渲染;Tauri 下建议解码后写入本地文件再展示,避免超大 data URL 占内存。
- gpt-image 系列额外返回 **token usage**(图像生成计费信息)。

**接入建议**:图像工作台的"生成"按钮 → `POST /v1/images/generations` → 拿 `b64_json` → Tauri 侧落盘 → 画廊网格展示 + 元数据(prompt/size/quality/seed)。与视频的异步队列可共用一套"生成任务 → 结果落盘 → 画廊"管线。
